## Standard Workflow

Every task in this repository follows this lifecycle:

```
Triage → Plan → Implement → Verify → PR → Post-PR
```

| Stage | Activity |
|-------|----------|
| **Triage** | Understand the bug/feature; reproduce if needed; assess scope |
| **Plan** | Break the work into steps; document in the PR checklist |
| **Implement** | Write code with minimal, focused changes |
| **Verify** | Lint, build, test; manually exercise the changed paths |
| **PR** | Open a pull request with a clear description and checklist |
| **Post-PR** | Address review comments; re-verify; merge |

## Filing a New Request

Use the [project request issue template](./.github/ISSUE_TEMPLATE/project-request.md) and fill in:

1. **PROJECT** — `SITEMATE` or `EDMONTON_LAND`
2. **GOAL** — a 1–3 line description of the bug, feature, or refactor
